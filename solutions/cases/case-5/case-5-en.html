Real case #5

Automated component requirements planning

The sales team creates orders for finished machines and production equipment. Each product has its own BOM defining the components and quantities required to build one unit. The system automatically converts finished-goods orders into total component demand, compares it with current stock levels and calculates exactly what still needs to be purchased.

Problem

Manual requirements planning quickly turns into a complex reconciliation exercise

Before automation, the buyer has to review each finished-goods order, open the relevant BOM, identify how many units of every component are required for one finished product and multiply those quantities by the actual order volume.

If the same component is used in several different products, the requirements have to be consolidated into a single total. Stock on hand, reservations and the actual shortage then need to be checked separately.

Whenever the ordered quantity changes or a product specification is updated, the entire calculation has to be repeated. This makes it easy to miss a component, count the same item twice, purchase too much or discover a shortage only when production is about to start.

Solution

The system automatically converts orders into exact purchasing requirements

The user enters the quantities of ordered machines and the current stock levels. The system automatically expands the BOM for every product and calculates the full component requirement.

Identical components used across different products are consolidated into a single line. The system then compares total demand with available inventory and calculates the actual shortage.

As a result, the buyer immediately sees exactly what needs to be purchased, in what quantity, and which items are already fully covered by stock. If order quantities or inventory levels change, a new calculation can be generated again in just a few seconds.
